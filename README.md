# RadSwift

**AI-drafted chest X-ray reports and AI worklist priority, tested for their effect on radiology report turnaround time.**

COMP-5112 Research Methodology, Lakehead University. Team: Vaibhav Sharma, Kirty Raj.

> Research prototype for a course project. Not a medical device. Not for clinical use.

## What the project does

1. **Fine-tunes a model** (ViT image encoder + T5-small text decoder) on 3,111 public chest X-ray studies so that it
   writes a draft report and gives an abnormal score for a frontal chest X-ray.
2. **Evaluates** the drafts and the score on 312 studies the model never saw, against two baselines.
3. **Simulates** a radiology department to estimate how much AI drafts and AI priority could change turnaround
   time, using the accuracy we measured in step 2.
4. **Demonstrates** the idea in a small app: worklist, report workspace, simulation.

## What is real and what is not

| Status | Applies to |
|---|---|
| **Implemented** | Data preparation, fine-tuned model, evaluation, abnormal score, demo app, workflow simulator |
| **Simulated** | Workflow timings, turnaround effects, arrival times shown in the demo worklist |
| **Assumed** | 26.6 h baseline and its stage split, staffing, reading times, workflow-gain percentages. Every value is listed with its reason in `config/workflow_assumptions.yaml` |
| **Future work** | Validation on hospital data, PACS/RIS integration, CT and MRI, lateral view, regulatory approval |

## The pipeline, in order

| Step | File | What it does | Runs on |
|---|---|---|---|
| 1 | `src/step1_generate_workflow_data.py` | Calibrates the simulator, writes three linked synthetic tables | laptop |
| 2 | `src/step2_analyze_workflow.py` | Merges and cleans the tables, stage means, statistical tests, charts | laptop |
| 3 | `src/step3_prepare_xray_data.py` | Selects and cleans the Indiana studies, splits 80/10/10, shrinks images | Kaggle |
| 4 | `src/step4_train_report_model.py` | Fine-tunes the model | Kaggle GPU |
| 5 | `src/step5_evaluate_report_model.py` | Scores the model on the test set, builds the demo bundle | Kaggle GPU |
| 6 | `src/step6_simulate_radswift.py` | Runs seven scenarios 30 times each, tests, sensitivity analysis | laptop |
| demo | `app/demo_app.py` | Streamlit demo | laptop |

Helper files: `src/workflow_sim.py` (the simulator), `src/report_model.py` (the model), `src/xray_dataset.py`
(image and text loading), `src/text_metrics.py` (cleaning and scoring). See `docs/FILE_GUIDE.md` for every file.

## How to run

```bash
pip install -r requirements.txt

python src/step1_generate_workflow_data.py
python src/step2_analyze_workflow.py
python src/step6_simulate_radswift.py
python tests/test_pipeline.py

streamlit run app/demo_app.py
```

Steps 3 to 5 need a GPU and the image dataset: open `notebooks/kaggle_train_and_evaluate.ipynb` on Kaggle and
follow the instructions in its first cell. Download `radswift_outputs.zip` at the end and unzip it into this folder.

## Data

- **Chest X-rays and reports:** Indiana University chest X-ray collection (Open-i, U.S. National Library of
  Medicine; Demner-Fushman et al., 2016), downloaded from Kaggle `raddar/chest-xrays-indiana-university`.
  Public and de-identified. Not stored in this repository. See `data/README.md`.
- **Workflow data:** synthetic, generated by Step 1. No real patients.

## Results

Numbers are quoted only from files in `results/` produced by our own runs.
`results/simulation_summary.csv` has a column `model_numbers_source`: it reads `measured` when Step 6 used
`results/metrics.json` from our evaluation, and `placeholder` when that file was missing.
Rows marked `placeholder` are not results.

## Limits

- One public dataset from one source; no hospital data and no radiologist judged the drafts.
- Frontal view only; chest X-rays only.
- Word-overlap scores (BLEU, ROUGE) do not measure clinical correctness. Our clinical check covers six
  findings with a simple negation rule.
- The workflow is a simulation built on assumptions. It shows what would follow if the assumptions held.
